What's different from plain text, and why

List Messages

Destination, hotel and room selection become tap-to-pick lists instead of "reply with a number" — no more mismatched numbers or typos, and it looks native to WhatsApp.

WhatsApp Cloud API · interactive/list
Quick Reply Buttons

Dates and guest count become one-tap buttons for the common cases, while still allowing free text for anything unusual (e.g. "Enter dates myself").

WhatsApp Cloud API · interactive/button
WhatsApp Flow (form)

Name, email and phone are collected in one native in-chat form instead of three separate free-text messages the bot has to parse and re-ask about when incomplete.

WhatsApp Cloud API · Flows
Rich Confirmation Card

The final booking summary becomes a clean visual card (still plain text under the hood — WhatsApp text messages support this kind of layout) instead of a wall of text.

Formatted text message
Important caveat

Buttons/lists/Flows require extra work: building the interactive JSON payloads Meta expects, handling button/list reply webhooks (a different payload shape than plain text), and Flows specifically need a published Flow JSON + endpoint. This prototype is purely visual — nothing here is wired up yet.
